"Well, OpenOffice wouldn't print on Tuesdays:“ What a fascinating bug!! My wife has complained that open office will never print on Tuesdays!?! Then she demonstrated it. Sure enough, won't print on Tuesday. Other applications print. I think this is the same bug. Here is my guess:Print to a postscript file. Observe the line: %%CreationDate: (Tue Mar 3 19:47:42 2009)Change "Tue" to anything else: %%CreationDate: (XTue Mar 3 19:47:42 2009)Save the file and it prints. Tools like evince work because they simply omit the "CreationDate" tag to begin with.Now something odd happens when my cups script (I am using the Brother MFC420CN) copies the file to a temp file. Some of the code is rearranged, not sure how or why, but it uses a command called "file" to identify the file as "PostScript". This check would work on the original file you printed, but by the time it runs the check on the temp file, it misidentifies. Normally it would return: PostScript document text conforming at level 3.0 But there is another check that happens before the PostScript check. If it finds "Tue" at the fourth byte of the file, it identifies it as: Jan 22 14:32:44 MET 1991\011Erlang JAM file - version 4.2 So it's not a problem w/ openoffice.org, cups, or the brother printer drivers. It is a bug in the `file` utility, and documented at https://bugs.launchpad.net/ubuntu/+source/file/+bug/248619. ”https://bugs.launchpad.net/ubuntu/+source/cupsys/+bug/255161..."

I'm making LLMs work on small and old devices

"For the last five months or so, opus and fable have both been able to do this task as a soneshot prompt. An inference engine is almost pure compute and to a first approximation the only operation your hardware needs to support to do llm inference is multiplication [the rest of an inference engine is "some trig"].So to get any model working on $OLD_HARDWARE, the hardest part of the task is now sourcing the hardware itself and giving the agent ssh access -- a modern agent will be able to source a compiler, write the implementation, optimize it, test in qemu (or any other simulator) and push it onto the device.Example prompt: "write an inference engine for qwen3 0.6b in pure assembly that runs on this device. Write a script to attach the weights to the resulting binary. Prefix is supplied as a stream of u32 token IDs on stdin. The engine streams u32 token IDs on stdout.""

"Recently I started this open source project at my AI company, where I'm trying to make LLMs workingNow Reached 16B models running on iPad Air 1st gen and xiaomi tv box, both have less than 1GB of usable memory, and reached some decent speeds given the hardware.I'm open sourcing the effort done, kernels developed and results for everyone to re-produce and push more, also the modified models are on hugging face : https://huggingface.co/hyperionaidevI want a more challenging device, what do you think?"

"This is very cool. Love the trend of optimizing small modelsI’ve been working on small local models and it’s amazing how fast the tech has progressedA year ago, I was creating conversational characters by finetuning a qwen 2.5 0.5b param model, and it worked pretty well.
